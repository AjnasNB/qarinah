## Existing baseline and funded work

Qarinah already provides local project memory, an append-only evidence ledger, rebuildable views, bounded cited context, and coding-agent integrations. Those existing capabilities are the baseline, not work newly delivered by this grant.

The proposed funded work strengthens security, interoperability, cross-platform release reproducibility, independently reproduced evidence, beginner onboarding, contributor participation, and maintenance. All funded deliverables, reports, specifications, fixtures, and code will be public. External assessment and reproduction are planned activities; findings and results must be reported with their limitations.

## Monthly milestones

| Month | Proposed work and deliverables |
| --- | --- |
| 1 — Baseline and participation | Publish the funded roadmap as tracked issues with acceptance criteria; document the release, security, privacy, and benchmark baselines; improve the contribution guide; and publish the first community progress update. |
| 2 — Interoperability | Publish a versioned specification, schemas, conformance fixtures, and compatibility tests for the event ledger, context packs, CLI, JavaScript API, and MCP integrations. |
| 3 — Reproducible releases | Verify clean installs and pinned-package interoperability on Linux, macOS, and Windows; document the release process; and publish CI and artifact receipts that an external maintainer can reproduce. |
| 4 — Independent security and privacy review | Commission an external assessment, triage every finding, remediate confirmed issues, and publish an appropriate report or advisory with the resulting security-response process. |
| 5 — Independent evidence and onboarding | Commission reproduction of the scoped public benchmarks; publish methods, results, limitations, and machine-readable receipts; and release a beginner-focused demo repository and installation path. |
| 6 — Community and sustainability | Complete small contributor bounties, publish maintenance and incident-response playbooks with response targets, hold a second public community review, and publish final outcomes and spending reports. |

## Completion evidence

Success means an external contributor can install Qarinah on all three supported desktop operating systems, verify the public specification and release evidence, reproduce the published benchmark fixtures, follow a documented security path, and make a first contribution.

Publish the funded issue outcomes, relevant assessment reports or advisories, reproduction methods and limitations, public implementation artifacts, and final spending report. Proposed external assessment does not constitute a current security certification, and project-specific benchmark evidence does not establish universal savings or performance.

Work or hours funded elsewhere must be disclosed and excluded or offset to avoid charging the same deliverable twice.
